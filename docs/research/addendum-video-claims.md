## O que entra no plano

- Template de Task Contract: Tarefa + Guardrails + Critérios de aceitação + "mostrar evidência, não afirmar sucesso" (fonte oficial confirmada, claim 2).
- Regra de poda de CLAUDE.md/pack: "removeria isso causaria erro? se não, corta" (best-practices oficial, claim 1) — sem usar o termo "product overhang".
- Ordem/estabilidade do pack para aproveitar prompt cache: manter tools e system prompt estáveis entre turnos; cache read é 10x mais barato (não 20x); TTL padrão 5 min, 1h é opção paga; troca de modelo/effort pode invalidar cache (exceto Fable 5.1 para effort) (claim 3).
- Nomes corretos de comandos de harness para handoff/poda: `/compact <instruções>`, `/rewind`, `/rename` + `--resume`, `/skill-doctor`, `/context`, `/cost`, `/usage` (claims 4 e 6).
- Padrão real de roteamento barato para missões longas: **Maker em modelo médio + Advisor de modelo forte via tool call sob demanda** (advisor tool da API, ou `/advisor` no Claude Code) — inverso do que o vídeo descreveu; combinar com `CLAUDE_CODE_SUBAGENT_MODEL`/`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`/`--model` por subagente para tarefas de fato triviais, e `/effort` para ajuste fino de custo por sessão (claim 5).

## O que descartar

- O termo "product overhang" (não é vocabulário oficial da Anthropic).
- O número "20x mais barato" para cache read (correto: 10x).
- "Advisor Mode delega tarefas simples a modelo menor" — o padrão oficial é o oposto (executor barato chama advisor caro sob demanda).
- "`/doctor` limpa CLAUDE.md e remove skills/MCPs antigos" como descrição do comportamento padrão — na prática ele só propõe cortes de CLAUDE.md e não mexe em skills/MCPs (isso é `/skill-doctor`).
- "Ferramentas de handoff" como nome de feature — não existe; usar os comandos reais (`/compact`, `/rewind`, `/rename`).
- "Ponytail"/"Caveman" como parte da stack oficial ou dependência do plano — são plugins de terceiros opcionais.
- `claude plugin eval` como algo verificado — não encontrado em fonte primária consultada.
